主播开播流程 + SRS 回调处理 + 直播状态机

主播开播完整流程

开播时序图
主播 → POST /api/v1/live/rooms/{id}/start
后端 ① 校验房间状态（必须为"预告"）
后端 ② 生成推流 Token（JWT, 有效期 2h）
后端 ③ 写入 Redis 白名单：live:push:whitelist:{roomId} = token（TTL 2h）
后端 ④ 返回推流地址：rtmp://host:1935/live/{roomId}?token={jwt}
主播 ⑤ 将地址填入 OBS → 开始推流
SRS → POST /api/v1/live/srs/callback (on_publish)
后端 ⑥ 验证 Redis 白名单 → 更新房间状态为"直播中"
后端 ⑦ 记录开播时间，清除 Redis 白名单

SRS 回调处理 Controller

新增 SrsCallbackController.java
@Tag(name = "SRS回调")
@RestController
@RequestMapping("/api/v1/live/srs")
@RequiredArgsConstructor
public class SrsCallbackController {

    private final SrsCallbackService srsCallbackService;

    /**
     * SRS 推流/断流回调
     * action: "on_publish" | "on_unpublish"
     */
    @PostMapping("/callback")
    public String callback(
            @RequestParam String app,
            @RequestParam String stream,
            @RequestParam String action,
            @RequestParam(required = false) String param) {
        // stream = roomId
        return srsCallbackService.handleCallback(app, stream, action, param);
    }

    /**
     * SRS 播放鉴权回调
     * 返回 "0" 允许播放，非 "0" 拒绝
     */
    @PostMapping("/on-play")
    public String onPlay(
            @RequestParam String stream,
            @RequestParam(required = false) String param) {
        return srsCallbackService.verifyPlayAccess(stream, param);
    }
}

Redis 状态缓存设计

Redis Key 设计

# 推流白名单（TTL 2h）
live:push:whitelist:{roomId} → token

# 直播间实时状态
live:room:{roomId}:online   → int (在线人数)
live:room:{roomId}:likes    → int (点赞计数)
live:room:{roomId}:status   → int (0/1/2/4)

# 弹幕限频
live:danmaku:{roomId}:{uid} → 1 (TTL 2s)

# 虚拟币余额
live:coin:{uid}             → int

状态同步策略

  • 写入时机：SRS 回调 → 更新 Redis + DB
  • 读取优先级：Redis > DB
  • 在线人数：WebSocket 连接/断开时 Redis 原子增减
  • 点赞计数：Redis 原子增，每 10 次批量写 DB
  • 异常恢复：服务重启时从 DB 加载状态到 Redis
