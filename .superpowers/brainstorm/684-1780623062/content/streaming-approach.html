直播技术路线选择

ShopMax 需要一套完整的直播推流/拉流方案。以下是三种主流路线：

A

自建流媒体服务器（推荐）

方案：使用开源 SRS (Simple Realtime Server) 或 ZLMediaKit，Docker 部署

协议：RTMP 推流 → HLS/HTTP-FLV/WebSocket-FLV 拉流

优势

  • 完全免费，无云服务费用
  • 学习价值高，理解底层原理
  • Docker 一键部署，与项目 MinIO/Redis 同架构
  • 支持录制、转码、截图等扩展

劣势

  • 需要公网 IP 或内网穿透才能外网访问
  • 性能受限于本机资源
B

云服务商直播 SDK

方案：阿里云直播 / 腾讯云直播 / 声网 Agora

协议：RTMP 推流 → CDN 分发 → HLS/FLV 拉流

优势

  • 开箱即用，稳定性高
  • 全球 CDN 加速，延迟低
  • 自带录制、转码、鉴黄等增值功能

劣势

  • 需要付费（按流量/时长计费）
  • 学习价值低，主要是调 API
  • 需要实名认证 + 企业资质（部分功能）
C

WebRTC 纯浏览器方案

方案：浏览器原生 WebRTC + 信令服务器

协议：WebRTC P2P/通过 SFU 中转

优势

  • 超低延迟（< 1s）
  • 无需安装推流软件（OBS）
  • 浏览器原生支持

劣势

  • 大规模观众场景需要 SFU/MCU 服务器
  • 移动端兼容性复杂
  • 不适合录制/回放场景
  • 实现复杂度最高

我的建议

对于 ShopMax 这个学习型电商项目，方案 A（自建 SRS）最合适：

  • 与现有 Docker/MinIO/Redis 架构一致，部署简单
  • 完全免费，适合学习和演示
  • SRS 社区活跃，文档完善，支持 RTMP/HLS/HTTP-FLV/WebRTC
  • 可以完整体验从推流到播放的全链路
