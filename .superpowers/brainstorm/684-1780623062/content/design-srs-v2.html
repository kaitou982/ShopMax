设计 · SRS 部署与配置（修正版）

修复：拉流鉴权 / DVR 自动清理 / Docker 网络兼容性

1. 拉流鉴权方案

使用 SRS on_play 回调验证观众身份：

srs.conf — on_play 鉴权
vhost __defaultVhost__ {
    http_hooks {
        enabled         on;
        on_publish      http://shop-live:8083/api/v1/live/srs/callback;
        on_unpublish    http://shop-live:8083/api/v1/live/srs/callback;
        on_play         http://shop-live:8083/api/v1/live/srs/on-play;
        on_stop         http://shop-live:8083/api/v1/live/srs/on-stop;
    }
}

HTTP-FLV 鉴权

观众携带 token 参数播放：
http://host:8085/live/{roomId}.flv?token={jwt}

SRS 触发 on_play → 后端验证 token → 返回 0 允许 / 非 0 拒绝

HLS 鉴权

HLS 无法逐请求鉴权，采用签名 URL方案：

/live/{roomId}.m3u8?token={jwt}&expire={ts}

Nginx 层校验签名，过期则 403。Token 有效期 30 分钟，前端自动续签。

2. DVR 录制自动清理

录制流程

  1. 直播中 → SRS 实时写入 FLV 到 /record/
  2. 直播结束 → on_unpublish 回调触发
  3. 后端异步任务：上传 FLV 到 MinIO
  4. 上传成功 → 更新 DB replay_url
  5. 删除本地 FLV 临时文件

清理策略

  • 即时清理：上传 MinIO 成功后立即删除本地文件
  • 兜底清理：定时任务每天凌晨扫描 /record/
  • 超过 24 小时的本地文件强制删除（防止上传失败堆积）
  • MinIO 中回放保留 30 天，过期自动删除
  • 配置项 live.replay.retention-days=30 可调整

定时任务设计

@Scheduled(cron = "0 0 3 * * ?")  // 每天凌晨 3 点
public void cleanupExpiredReplays() {
    // 1. 删除 MinIO 中超过 retention-days 的回放文件
    // 2. 删除本地 /record/ 中超过 24h 的残留文件
    // 3. 更新 DB 中过期回放的 replay_url 为 null
}

3. Docker 网络兼容性修正

弃用 host.docker.internal，改用 Docker 共享网络 + 容器名通信：

docker-compose.yml（修正）
services:
  srs:
    image: ossrs/srs:6
    ports:
      - 1935:1935   # RTMP
      - 8085:8080   # HTTP-FLV/HLS
      - 1985:1985   # HTTP API
    volumes:
      - ./docker/srs/conf:/usr/local/srs/conf
      - ./docker/srs/record:/usr/local/srs/record
    networks:
      - shopmax-net
    restart: unless-stopped

  minio:
    # ... 已有配置 ...
    networks:
      - shopmax-net

networks:
  shopmax-net:
    driver: bridge

❌ 之前的问题

  • host.docker.internal 仅 Docker Desktop 自动支持
  • Linux 需手动加 extra_hosts
  • 回调地址硬编码，环境切换需改配置

✅ 修正方案

  • 所有容器加入 shopmax-net 共享网络
  • SRS 回调地址用容器名：http://shop-live:8083/...
  • 跨平台兼容，无需 extra_hosts
  • 后端服务地址通过环境变量注入
