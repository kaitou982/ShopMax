设计 · SRS 流媒体服务器部署

Docker 部署 SRS 6.0，与现有 MinIO/Redis 同架构

Docker Compose 配置

docker-compose.yml 新增 srs 服务
services:
  srs:
    image: ossrs/srs:6
    ports:
      - 1935:1935   # RTMP 推流端口
      - 8085:8080   # HTTP-FLV/HLS 端口
      - 1985:1985   # SRS HTTP API
    volumes:
      - ./docker/srs/conf:/usr/local/srs/conf
      - ./docker/srs/data:/usr/local/srs/data
      - ./docker/srs/record:/usr/local/srs/record
    restart: unless-stopped

SRS 核心配置

docker/srs/conf/srs.conf
# 监听端口
listen              1935;
http_api {
    enabled         on;
    listen          1985;
}
http_server {
    enabled         on;
    listen          8080;
    dir             ./objs/nginx/html;
}

# 推流回调鉴权
vhost __defaultVhost__ {
    http_hooks {
        enabled         on;
        on_publish      http://host.docker.internal:8080/api/v1/live/srs/callback;
        on_unpublish    http://host.docker.internal:8080/api/v1/live/srs/callback;
    }
    # HLS 配置
    hls {
        enabled         on;
        hls_fragment    2;
        hls_window      10;
        hls_path        ./objs/nginx/html;
        hls_m3u8_file   [app]/[stream].m3u8;
        hls_ts_file     [app]/[stream]-[seq].ts;
    }
    # FLV 录制
    dvr {
        enabled         on;
        dvr_path        ./record/[app]/[stream].[timestamp].flv;
        dvr_plan        session;
    }
}

关键设计点

推流地址格式

rtmp://localhost:1935/live/{roomId}?token={jwt}
  • roomId = 直播间 ID
  • token = 推流鉴权 JWT（有效期 2 小时）
  • 后端生成地址时写入 Redis 白名单
  • SRS on_publish 回调时验证白名单

拉流地址格式

HTTP-FLV: http://localhost:8085/live/{roomId}.flv
HLS: http://localhost:8085/live/{roomId}.m3u8

拉流无需鉴权，任何观众可访问

Gateway 路由新增

SRS 的 HTTP 端口（8085）直接暴露，不经过 Gateway：

  • /ws/live/** → shop-live-service（已有，WebSocket 互动）
  • SRS HTTP-FLV/HLS → 独立端口 8085（不走 Gateway，减轻压力）
  • SRS HTTP API (1985) → 内部使用，不对外暴露
